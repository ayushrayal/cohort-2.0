1. WHAT IS JAVASCRIPT? - COMPLETE ARCHITECTURE
================================================================================

DEFINITION:
JavaScript is a high-level, interpreted, just-in-time compiled programming language 
that conforms to the ECMAScript specification.

KEY ARCHITECTURAL COMPONENTS:

1. JavaScript Engine:
   - V8 (Chrome, Node.js) - Most popular
   - SpiderMonkey (Firefox)
   - JavaScriptCore (Safari)
   - Chakra (Edge - legacy)

2. Runtime Environment:
   - Browser: DOM, BOM, Web APIs
   - Node.js: File System, Network, Process

3. Execution Context:
   - Global Execution Context
   - Function Execution Context
   - Eval Execution Context

4. Call Stack:
   - LIFO (Last In, First Out) structure
   - Tracks function execution order
   - Stack overflow prevention

HOW JAVASCRIPT WORKS BEHIND THE SCENES:

1. Parsing: Code → AST (Abstract Syntax Tree)
2. Compilation: JIT (Just-In-Time) compilation
3. Execution: Bytecode execution with optimization
4. Garbage Collection: Memory management

2. SCRIPTING LANGUAGE - TYPES AND CHARACTERISTICS
================================================================================

DEFINITION:
A scripting language is a programming language that is interpreted at runtime 
rather than compiled beforehand.

TYPES OF SCRIPTING LANGUAGES:

1. Client-side Scripting:
   - Executes in user's browser
   - Examples: JavaScript, TypeScript
   - Purpose: DOM manipulation, form validation, animations

2. Server-side Scripting:
   - Executes on web server
   - Examples: Node.js, PHP, Python, Ruby
   - Purpose: Database operations, file handling, API creation

3. Shell Scripting:
   - Executes in operating system shell
   - Examples: Bash, PowerShell, Shell scripts
   - Purpose: System administration, automation

CHARACTERISTICS OF SCRIPTING LANGUAGES:

1. Interpreted: No compilation step required
2. Dynamic Typing: Types determined at runtime
3. High-level: Abstraction from hardware
4. Automatic Memory Management: Garbage collection
5. Platform Independent: Write once, run anywhere

JAVASCRIPT AS SCRIPTING LANGUAGE:

- Originally designed for client-side scripting in browsers
- With Node.js, became full-stack language
- Single-threaded with event-driven, non-blocking I/O
- Prototype-based object-oriented programming

3. HISTORY AND EVOLUTION OF JAVASCRIPT
================================================================================

TIMELINE:

1995 - BIRTH:
- Created by Brendan Eich at Netscape in 10 days
- Originally called "Mocha", then "LiveScript"
- Renamed to "JavaScript" for marketing (Java was popular)

1996 - 1997 - STANDARDIZATION:
- Microsoft reverse-engineered as "JScript"
- Submitted to ECMA International for standardization
- ECMAScript 1 (ES1) released - First official standard

1998 - 2009 - SLOW EVOLUTION:
- ES3 (1999): Regular expressions, try/catch, formatting
- ES4 (Abandoned): Too ambitious, caused division
- ES5 (2009): Strict mode, JSON support, array methods

2015 - MODERN JAVASCRIPT (ES6/ES2015):
- let/const, arrow functions, classes, modules
- Promises, template literals, destructuring
- Default parameters, rest/spread operators

2016+ - YEARLY UPDATES:
- ES2016: Array.prototype.includes, exponentiation operator
- ES2017: Async/await, Object.values(), Object.entries()
- ES2018: Rest/spread properties, Promise.finally()
- ES2019: Array.flat(), Object.fromEntries()
- ES2020+: Optional chaining, nullish coalescing

4. VARIABLES: var, let, const - COMPLETE MECHANISM
================================================================================

MEMORY ALLOCATION:

var:
- Function-scoped or global
- Hoisted with undefined initialization
- Stored in Variable Environment
- Can be redeclared and reassigned

let/const:
- Block-scoped ({ } scope)
- Hoisted but in Temporal Dead Zone (TDZ)
- Stored in Lexical Environment
- Cannot be redeclared in same scope

INTERNAL WORKING:

1. Creation Phase:
   - Memory allocated for variables and functions
   - var: initialized with undefined
   - let/const: uninitialized (TDZ)

2. Execution Phase:
   - Code executed line by line
   - Assignments happen
   - TDZ ends when declaration is encountered

EXAMPLES WITH MEMORY VISUALIZATION:

// PHASE 1: CREATION
// Memory allocated:
//   a: undefined (var)
//   b: <uninitialized> (let) - TDZ
//   c: <uninitialized> (const) - TDZ

// PHASE 2: EXECUTION
console.log(a); // undefined
var a = 10;

// console.log(b); // ReferenceError (TDZ)
let b = 20;

const c = 30;

5. SCOPE - COMPLETE CHAIN MECHANISM
================================================================================

TYPES OF SCOPE:

1. Global Scope:
   - Accessible throughout the program
   - Variables declared outside any function
   - In browsers: attached to window object

2. Function Scope:
   - Variables accessible only within function
   - Created for each function invocation
   - var variables are function-scoped

3. Block Scope:
   - Variables accessible only within { } blocks
   - let and const are block-scoped
   - Includes if, for, while, switch blocks

4. Lexical Scope (Static Scope):
   - Scope determined by code structure
   - Inner functions have access to outer scopes
   - Forms scope chain

SCOPE CHAIN MECHANISM:

function outer() {
    let outerVar = "I'm outside";
    
    function inner() {
        let innerVar = "I'm inside";
        console.log(outerVar); // Works - scope chain
        console.log(innerVar); // Works - current scope
    }
    
    inner();
}

SCOPE CHAIN: inner() → outer() → global

CLOSURES:
- Function + its lexical environment
- Preserves scope chain even after outer function execution
- Used for data encapsulation and private variables

6. REASSIGNMENT vs REDECLARATION - MEMORY PERSPECTIVE
================================================================================

REASSIGNMENT:
- Changing the value of existing variable
- Memory address may or may not change
- Depends on data type (primitive vs reference)

REDECLARATION:
- Creating new variable with same name in same scope
- Different memory allocation
- Only allowed with var

DETAILED BREAKDOWN:

// PRIMITIVE TYPES (Value storage)
let a = 10;     // Memory: a → 10
a = 20;         // Memory: a → 20 (reassignment)

// let a = 30;   // Error: redeclaration not allowed

// REFERENCE TYPES (Pointer storage)
let obj1 = {x: 1};  // Memory: obj1 → address1 → {x: 1}
obj1 = {y: 2};      // Memory: obj1 → address2 → {y: 2} (reassignment)

// var allows both
var x = 10;
var x = 20;     // Redeclaration allowed
x = 30;         // Reassignment allowed

7. TEMPORAL DEAD ZONE (TDZ) - COMPLETE UNDERSTANDING
================================================================================

DEFINITION:
The time between entering scope and variable declaration where the variable 
cannot be accessed.

TDZ RULES:
1. Variable exists but is uninitialized
2. Accessing variable throws ReferenceError
3. TDZ ends when execution reaches declaration
4. Applies to let and const, not var

MECHANISM:

{
    // TDZ START for 'x'
    // console.log(x); // ReferenceError
    // TDZ CONTINUES...
    let x = 42;
    // TDZ ENDS - x can be accessed
    console.log(x); // 42
}

WHY TDZ EXISTS:

1. Catch Errors Early: Prevents using variables before declaration
2. Better Code Quality: Encourages declaring variables at top
3. Predictable Behavior: No silent undefined like var

REAL-WORLD TDZ SCENARIOS:

// Scenario 1: Function in TDZ
{
    // console.log(myFunc()); // ReferenceError
    let myFunc = function() { return "Hello"; };
}

// Scenario 2: Complex TDZ
function tdzExample(value) {
    // console.log(typeof myVar); // ReferenceError
    let myVar = value * 2;
    return myVar;
}

8. HOISTING - COMPLETE MECHANISM
================================================================================

WHAT IS HOISTING:
JavaScript's behavior of moving declarations to the top of their containing 
scope during compilation phase.

TYPES OF HOISTING:

1. Variable Hoisting:
   - var: hoisted and initialized with undefined
   - let/const: hoisted but not initialized (TDZ)
   - function: hoisted with full definition
   - class: hoisted but not initialized (TDZ)

2. Function Hoisting:
   - Function declarations: fully hoisted
   - Function expressions: follow variable hoisting rules

DETAILED EXAMPLES:

// VARIABLE HOISTING
console.log(a); // undefined (var hoisted)
var a = 10;

// console.log(b); // ReferenceError (let in TDZ)
let b = 20;

// FUNCTION HOISTING
sayHello(); // "Hello" (function declaration hoisted)
function sayHello() {
    console.log("Hello");
}

// sayHi(); // TypeError (var hoisted as undefined)
var sayHi = function() {
    console.log("Hi");
};

INTERNAL PROCESS:

// PHASE 1: COMPILATION (Hoisting)
// Memory allocated:
//   var x: undefined
//   function y: complete function
//   let z: <uninitialized>

// PHASE 2: EXECUTION
// Code runs line by line

9. WHY var LEAKS, let DOESN'T - SCOPE MECHANISM
================================================================================

FUNCTION SCOPE vs BLOCK SCOPE:

// FUNCTION SCOPE (var)
function test() {
    if (true) {
        var leaked = "I leak to function scope";
    }
    console.log(leaked); // Works - leaked to function scope
}

// BLOCK SCOPE (let)
function test() {
    if (true) {
        let contained = "I stay in block";
    }
    // console.log(contained); // Error - block scoped
}

MECHANISM EXPLANATION:

var:
- Scoped to entire function or global context
- No concept of block scope
- Hoisted to top of function/global scope

let/const:
- Scoped to nearest enclosing block
- Respects { } boundaries
- Not accessible outside block

REAL-WORLD IMPACT:

// Problem with var in loops
for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100); // 3, 3, 3
}

// Solution with let
for (let j = 0; j < 3; j++) {
    setTimeout(() => console.log(j), 100); // 0, 1, 2
}

REASON: let creates new binding for each iteration, var shares same binding.

10. const WITH OBJECTS - MUTATION VS REASSIGNMENT
================================================================================

CONST PRINCIPLE:
const creates an immutable binding, not an immutable value.

DETAILED EXPLANATION:

// REASSIGNMENT (Not allowed)
const person = { name: "John" };
// person = { name: "Jane" }; // TypeError: Assignment to constant

// MUTATION (Allowed)
person.name = "Jane";        // ✅ Allowed
person.age = 30;             // ✅ Allowed
delete person.name;          // ✅ Allowed

MEMORY PERSPECTIVE:

const obj = { x: 1 };
// Memory: obj → address1 → { x: 1 }

obj.x = 2;    
// Memory: obj → address1 → { x: 2 } (same address, content changed)

// obj = { y: 1 };  
// Memory: obj → address2 → { y: 1 } (different address - NOT ALLOWED)

HOW TO MAKE OBJECTS IMMUTABLE:

1. Object.freeze():
   const frozen = Object.freeze({ x: 1 });
   frozen.x = 2; // Silent failure in non-strict mode

2. Object.defineProperty():
   const obj = {};
   Object.defineProperty(obj, 'x', { value: 1, writable: false });

3. Using Patterns:
   - Always return new objects instead of mutating
   - Use libraries like Immutable.js

11. TRUTHY & FALSY VALUES - COMPLETE LIST AND BEHAVIOR
================================================================================

FALSY VALUES (6 total):
1. false
2. 0 (zero)
3. -0 (negative zero)
4. "" (empty string)
5. null
6. undefined
7. NaN

TRUTHY VALUES (Everything else):
- true
- "0" (string zero)
- "false" (string false)
- [] (empty array)
- {} (empty object)
- function(){} (empty function)
- 42 (any non-zero number)
- "hello" (any non-empty string)

SPECIAL CASES:

// Empty arrays and objects are truthy
if ([]) { console.log("Empty array is truthy"); }     // ✅
if ({}) { console.log("Empty object is truthy"); }    // ✅

// String "0" and "false" are truthy
if ("0") { console.log("String zero is truthy"); }    // ✅
if ("false") { console.log("String false is truthy"); } // ✅

// All objects are truthy
if (new Boolean(false)) { console.log("Boolean object is truthy"); } // ✅

PRACTICAL USAGE:

// Default values
function greet(name) {
    name = name || "Guest"; // Use "Guest" if name is falsy
    return `Hello ${name}`;
}

// Conditional rendering
const message = userInput || "Default message";

// Validation
if (!email) {
    throw new Error("Email is required");
}

================================================================================

PRIMITIVE TYPES (7):

1. String: Text data, immutable
2. Number: Floating-point numbers, integers
3. Boolean: true/false
4. Undefined: Variable declared but not assigned
5. Null: Intentional absence of value
6. Symbol: Unique and immutable primitive
7. BigInt: Arbitrary precision integers

REFERENCE TYPES:

1. Object: Key-value collections
2. Array: Ordered lists
3. Function: Callable objects
4. Date: Date and time
5. RegExp: Regular expressions
6. Map: Key-value collections with any keys
7. Set: Collections of unique values

MEMORY MANAGEMENT:

PRIMITIVES:
- Stored directly in variable location
- Passed by value
- Compared by value

let a = 10;     // Memory: a → 10
let b = a;      // Memory: b → 10 (copy)
b = 20;         // Memory: b → 20, a → 10 (unchanged)

REFERENCES:
- Stored as reference to memory location
- Passed by reference
- Compared by reference

let obj1 = {x: 1};  // Memory: obj1 → address1 → {x: 1}
let obj2 = obj1;    // Memory: obj2 → address1 → {x: 1}
obj2.x = 2;         // Memory: obj1.x = 2, obj2.x = 2 (both changed)

13. DYNAMIC TYPING - RUNTIME TYPE SYSTEM
================================================================================

DEFINITION:
Type checking happens at runtime rather than compile time.

CHARACTERISTICS:

1. No Type Declarations:
   let x = 10;        // Number
   x = "hello";       // String - no error

2. Automatic Type Conversion:
   "5" + 3 = "53"     // Number to string
   "5" - 3 = 2        // String to number

3. Flexible but Error-Prone:
   - More concise code
   - Runtime type errors possible
   - Requires careful testing

TYPE INFERENCE:

let a = 42;           // inferred as number
let b = "hello";      // inferred as string  
let c = true;         // inferred as boolean
let d = {};           // inferred as object

BENEFITS AND DRAWBACKS:

Benefits:
- Faster development
- More flexible code
- Less boilerplate

Drawbacks:
- Runtime errors
- Harder to debug
- No IDE type hints

MODERN SOLUTIONS:
- TypeScript (static typing superset)
- JSDoc comments
- Strict mode and linters

14. typeof QUIRKS - HISTORICAL REASONS
================================================================================

STANDARD BEHAVIOR:
typeof "hello"         // "string"
typeof 42             // "number"  
typeof true           // "boolean"
typeof undefined      // "undefined"
typeof function(){}   // "function"

QUIRKS AND REASONS:

1. typeof null === "object"
   - Historical bug from first JavaScript implementation
   - Couldn't be fixed due to backward compatibility
   - Binary representation: object type tag + null pointer

2. typeof [] === "object"
   - Arrays are objects in JavaScript
   - Use Array.isArray() for proper checking

3. typeof NaN === "number"
   - NaN is technically a numeric value
   - Represents failed numeric operations
   - Part of IEEE 754 floating-point standard

4. typeof new String() === "object"
   - Primitive vs Object wrappers
   - new String() creates String object, not primitive

PROPER TYPE CHECKING:

// For null
value === null

// For arrays
Array.isArray(value)

// For NaN
Number.isNaN(value)

// For custom types
Object.prototype.toString.call(value)

15. TYPE COERCION - COMPLETE RULES
================================================================================

IMPLICIT COERCION RULES:

1. + Operator:
   - If any operand is string, convert both to string
   - Otherwise, convert to number

2. - * / % Operators:
   - Convert both operands to numbers

3. == Operator:
   - Complex rules based on operand types
   - Avoid using, prefer ===

4. Boolean Context (if, &&, ||, !):
   - Convert to boolean using truthy/falsy rules

COERCION TABLE:

Value          To String      To Number    To Boolean
""             ""             0            false
"0"            "0"            0            true
"1"            "1"            1            true  
"hello"        "hello"        NaN          true
0              "0"            0            false
1              "1"            1            true
true           "true"         1            true
false          "false"        0            false
null           "null"         0            false
undefined      "undefined"    NaN          false
[]             ""             0            true
[1]            "1"            1            true
[1,2]          "1,2"         NaN          true
{}             "[object Object]" NaN       true

== VS ===:

// == (Abstract Equality) - With coercion
"5" == 5          // true
0 == false        // true
"" == false       // true
null == undefined // true

// === (Strict Equality) - No coercion  
"5" === 5         // false
0 === false       // false
"" === false      // false
null === undefined // false

16. WHY NaN IS A NUMBER - TECHNICAL REASONS
================================================================================

TECHNICAL DEFINITION:
NaN is a special value of the Number type that represents "Not a Number".

WHY IT'S A NUMBER:

1. IEEE 754 Standard:
   - JavaScript uses IEEE 754 floating-point numbers
   - NaN is part of this standard as a numeric value
   - Represents invalid floating-point operations

2. Mathematical Operations:
   - 0 / 0 = NaN (mathematically undefined)
   - Math.sqrt(-1) = NaN (imaginary numbers)
   - "hello" * 5 = NaN (invalid operation)

3. Type Consistency:
   - All arithmetic operations return numbers
   - Failed operations need to return a number type
   - Prevents breaking the type system

NaN PROPERTIES:

1. NaN === NaN returns false
   - By IEEE 754 specification
   - Use Number.isNaN() or Object.is()

2. typeof NaN === "number"
   - Consistent with technical definition

3. isNaN() vs Number.isNaN():
   - isNaN("hello") // true (coercion)
   - Number.isNaN("hello") // false (no coercion)

PROPER NaN CHECKING:

// Correct ways:
Number.isNaN(value)
Object.is(value, NaN)
value !== value  // Only NaN is not equal to itself

// Incorrect ways:
value === NaN    // Always false
isNaN(value)     // Coercion happens

17. undefined vs null - PHILOSOPHICAL DIFFERENCE
================================================================================

UNDEFINED:
- "Variable exists but has no value"
- System-level absence of value
- Automatic by JavaScript engine

NULL:
- "Variable exists and has explicit empty value"
- Program-level absence of value
- Intentional by programmer

TECHNICAL DIFFERENCES:

               undefined        null
Type           "undefined"      "object"
JSON           excluded         included
Arithmetic     NaN              0
Default        Automatic        Manual

PRACTICAL USAGE:

// undefined scenarios
let x;                    // undefined - not assigned
function foo() {}         // returns undefined
obj.nonExistentProperty   // undefined - doesn't exist

// null scenarios  
let user = null;          // explicitly no user
document.getElementById("nonexistent") // null - not found

CONVERSION BEHAVIOR:

Number(undefined)    // NaN
Number(null)         // 0

String(undefined)    // "undefined"  
String(null)         // "null"

Boolean(undefined)   // false
Boolean(null)        // false

BEST PRACTICES:

1. Use null for intentional absence
2. Let undefined happen naturally
3. Check for both in validations
4. Use default parameters for undefined

function greet(name = "Guest") {
    // name will be "Guest" if undefined, not null
    return `Hello ${name}`;
}

19. !! FOR TRUTHINESS - COMPLETE MECHANISM
================================================================================

WHAT !! DOES:
Converts any value to its boolean equivalent.

HOW IT WORKS:
!value    // First ! converts to boolean and negates
!!value   // Second ! negates again to get actual boolean

STEP-BY-STEP:

let value = "hello";

!value   → !"hello" → !true → false
!!value  → !false → true

EQUIVALENT TO:
Boolean(value)

COMMON USE CASES:

1. Conditional Checks:
   if (!!userInput) {
       // Equivalent to: if (Boolean(userInput))
   }

2. Return Boolean Values:
   function hasData(data) {
       return !!data; // Always returns boolean
   }

3. React/JSX Conditions:
   {!!items.length && <List items={items} />}

4. Form Validation:
   const isValid = !!email && !!password;

ALTERNATIVES:

// These are equivalent:
!!value
Boolean(value)
value ? true : false

PERFORMANCE:
- !! is fastest (native operations)
- Boolean() is slightly slower (function call)
- Ternary is slowest (conditional logic)

READABILITY:
- !! is concise but may be confusing for beginners
- Boolean() is more explicit
- Choose based on team preference
